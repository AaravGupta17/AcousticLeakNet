## 2. Challenging the few-shot reframing

Per your instruction, zero-label remains the primary target; few-shot is the fallback. Walking the four questions in order:

**A. Can pure zero-label transfer be meaningfully tested with our data?** Yes — and it already has been, repeatedly, before Version 2 was even proposed. `experiments/cross_dataset.py` (E9) already ran a leave-one-**source**-out zero-label test with four different methods (loudness-free logreg, CNN from scratch, CNN pretrained on synthetic, frozen-encoder probe) across all three sources. Results (`results/runs/2026-09-29_010352_e9_cross_dataset.json`, read directly for this review):

| Held out | logreg | cnn_scratch | cnn_pre | probe |
|---|---|---|---|---|
| Dongguan | 0.66 | 0.66 | 0.68 | 0.36 |
| Hong Kong hydrophone | **0.16** | 0.42 | 0.49 | **0.69** |
| Hong Kong noise logger | 0.43 | 0.54 | 0.60 | 0.61 |
| Mendeley accelerometer | 0.50 | 0.34 | 0.49 | 0.43 |
| Mendeley hydrophone | 0.49 | 0.60 | 0.58 | 0.38 |

No held-out source clears chance consistently across methods, and on Hong Kong hydrophone the four methods don't even agree on *direction* (0.16 vs 0.69 is not "noisy around a weak real effect," it's four methods disagreeing about which class is which). This is Benchmark 1 from your framing — it already exists, already ran, and the honest reading is a replicated null with high method-to-method variance, consistent with `docs/MODEL_F_PREREG.md`'s own pre-Model-F diagnosis ("real sources do not transfer to each other, leave-one-source-out AUROC mostly 0.45-0.65").

**B. Can synthetic + multiple real sources improve transfer?** This is genuinely untested, not just difficult. Model F mixes synthetic and real training in every run, so no experiment in this project isolates whether adding synthetic data *helps* versus real-only training on the same held-out target — the ablation needed is cheap (train E9's `cnn_scratch`/`cnn_pre` protocol with and without a synthetic-only training arm added, same held-out target, same seeds) and should be run before committing to a more complex alignment-loss design.

**C. Can unlabeled target-domain adaptation improve transfer?** Also untested — no adaptation method of any kind exists in this codebase yet. This is the most promising unexplored axis, not CORAL/MMD: **AdaBN-style BatchNorm statistics recalibration using unlabeled target windows** needs no labels, no gradient step, and cannot reinforce a confidently-wrong prediction the way Tent/SHOT can (confirmed unsafe in §1) — it only recenters/rescales feature statistics. It is also the *only* zero-label-compatible method that is not blocked by the single-class-per-site confound in §3, because it operates on marginal feature statistics, not on label-conditioned alignment.

**D. Only then: how much labeled data is necessary?** Kept as the fallback axis per your instruction — see §5/§9 for exactly where it applies and where it's structurally broken (Hong Kong/Dongguan).

**Can these datasets support a scientifically valid cross-domain leak-detection experiment?**

**Not uniformly — and the original V2 document's Section E design (treating `f`/`f_nohk`/`f_nodg` as three interchangeable leave-one-domain-out rotations) overstates what two of the three rotations can show.** Specifically:

- **Hong Kong**: no experiment using this source as a held-out *test* domain can distinguish "detects the physical leak" from "recognizes this site," full stop — the confound is total (0% site overlap). This is exactly what `docs/ACOUSTICLEAKNET_R2_RESULTS.md` already concluded, now independently confirmed at the file level rather than inferred.
- **Dongguan**: mostly the same limitation, **except** for the 8 matched-trial pairs, which is new information not previously surfaced in this project's documentation — these 8 trials share material, zone, and sensor across the leak/no-leak split and are a genuine (if small), previously-unexploited, less-confounded sub-sample.
- **Mendeley Looped**: the only source where a held-out-domain leak/no-leak experiment is not structurally confounded by site identity. It still carries a suspected (unresolved) flow-condition confound, and its sample size is tiny (4 no-leak, 16 leak recordings), but it is the only one of the three where "the model learned to detect leaks" and "the model learned to recognize this site" are not synonymous by construction.

**What additional data structure is actually needed** (not a workaround, an honest answer to "what's missing"): genuinely **paired** leak/no-leak recordings at the same physical site — the same pipe, same sensor, monitored both during a leak and during normal operation. This project already has one concrete, unexploited lead toward exactly that: `experiments/public_data.py`'s own docstring notes the Hong Kong **MEMS accelerometer** files (currently excluded for lacking a confirmed sampling rate) have file names suggesting "before/after recordings with the same sensors" at the same sites — i.e., possibly the one real paired dataset already sitting in this project's downloaded data, unused. Resolving that sampling-rate question (contacting the dataset authors, or inferring the rate from the signal's known spectral content) is a concrete, low-cost Week 1 task, not a hypothetical future data-collection effort.

## 4. Three different problems, kept separate

- **Problem A (real → real cross-domain generalization)**: answerable only via Mendeley as the held-out target, given §3; Hong Kong/Dongguan rotations measure domain-recognition capability, not leak generalization, and should be reported and labeled as such, not folded into the same claim.
- **Problem B (synthetic → real transfer)**: already tested extensively (E4, Model F H2); established result is zero-shot failure/instability (R1). Still open: whether synthetic data helps *in combination* with real sources versus real-only (§2B), which is untested.
- **Problem C (unsupervised/few-shot adaptation to a new real domain)**: untested in any form in this codebase. The most tractable, highest-value open question in the whole program.

The original V2 document's Section E collapsed A and B together by treating all three leave-one-domain-out rotations as equivalent instances of the same benchmark. They are not: only the Mendeley rotation is a clean instance of A+B combined without the confound; the Hong Kong/Dongguan rotations are valid only as instances of B tested against a domain-recognition-confounded target, which is worth reporting but is not the same claim.

## 5. Benchmark design, explicit, impossible ones marked

- **Benchmark 1 (real → real LODO)**: valid with Mendeley as target; confound-limited (report as a secondary/diagnostic result, not a generalization claim) with Hong Kong or Dongguan as target, except for Dongguan's 8 matched-trial subset, which could be carved out as a small, separately-valid sub-benchmark if the loader is changed to not bake the label into the Dongguan group id for those specific trials.
- **Benchmark 2 (synthetic + real sources → held-out real)**: same per-domain validity as Benchmark 1; additionally requires the untested synthetic-contribution ablation from §2B to be meaningful rather than assumed.
- **Benchmark 3 (+ unlabeled target data)**: valid wherever Benchmark 1/2 is valid, and is **not weakened** by the single-class confound provided the adaptation method only touches marginal statistics (AdaBN) rather than anything label-conditioned (Tent/SHOT, ruled unsafe in §1).
- **Benchmark 4 (+ k ∈ {1,5,10} labeled target recordings)**: valid, as originally scoped, for Mendeley. **Not well-defined as originally scoped for Hong Kong/Dongguan**: a k-shot linear probe needs at least one example of each class, and no single Hong Kong or Dongguan site provides both — drawing k recordings across several confounded sites to get both classes would let the probe re-learn "site predicts label" instead of a transferable cue, silently defeating the point of the calibration step. If this benchmark is run on Hong Kong/Dongguan at all, it must draw its k shots from across multiple sites by design and this limitation must be stated alongside any result, not discovered after the fact.

## 6. CORAL/MMD against the actual alternatives

Re-evaluated with the corrected literature picture from §1:

1. **AdaBN (BatchNorm statistics recalibration on unlabeled target data)** — promoted to **co-primary candidate**. Needs no labels, no gradient step, cannot reinforce confidently-wrong predictions (unlike Tent/SHOT), and is the only method here immune to the single-class-target confound (§5, Benchmark 3). Nearly free to implement — `experiments/cross_dataset.py`'s existing `probe` protocol already freezes the encoder and keeps synthetic BatchNorm statistics in eval mode; recalibrating those statistics on unlabeled target windows is a small, well-scoped change to existing code, not new infrastructure.
2. **CORAL/MMD marginal alignment** — kept as a candidate, but its selection is **gated on actually reading `TL-Fault-Diagnosis-Library`'s result tables** (§1: the "best method" claim was unverified) before committing engineering time to porting it. If CORAL/MMD turns out to be a middling method in that library's own benchmark, a different method the library implements (e.g. DAN/MMD proper, or MixStyle, which is designed for exactly this kind of domain-randomization-adjacent setting) may be a better port target. This is a 1-2 hour reading task, not a redesign.
3. **Domain randomization** — already substantially implemented. Model F's `augment_f.py` (random EQ, random channel coherence/lag, multi-source backgrounds) *is* a domain-randomization strategy; it is the baseline to beat, not a new candidate to add.
4. **k-shot calibration (linear probe)** — kept as the fallback per §2, valid for Mendeley, conditionally valid for Hong Kong/Dongguan per §5's caveat.
5. **Self-supervised / contrastive pretraining on the project's own unlabeled real audio** — a **new candidate surfaced by this review**, not in the original V2 document. Because it only needs unlabeled real audio, it is unaffected by the single-class-per-site confound, reuses data already on disk, and is now better-supported by the corrected literature (§1's two general-audio sim-to-real SSL counterexamples) than previously credited. Still correctly scoped as a stretch/parallel-track item, not the flagship, given October's compute and engineering budget.
6. **IRM** — kept deprioritized, now for the correct, narrower reason (§1): no formal guarantee applies at 3-4 environments without knowing our feature dimensionality, not "provably fails."
7. **Tent/SHOT/pseudo-labeling** — still excluded; the mechanism argument (reinforcing confident errors on an all-one-class target) holds regardless of the new DCASE evidence, and that evidence (target-domain AUC as the dominant, unsolved bottleneck across DCASE editions) is independently consistent with excluding methods that assume a self-correcting signal is present in the target batch.

## 7. A better model than Model F — the representation question

Current architecture (`model_C/model.py`, unchanged since Model C): raw two-channel waveform input, 1D-CNN channel encoder, a cross-channel gate that is provably time-constant (`tests/test_model.py::test_gate_is_constant_over_time`, `docs/CLAIMS.md`) and therefore not a timing/TDOA mechanism, z-scored and 2 kHz band-limited per Model F. No spectrogram stage, no pretrained embedding, no self-supervised component anywhere in the pipeline.

Capacity is not the bottleneck: the same encoder already reaches 0.971 AUROC in-domain on Dongguan (`docs/MODEL_F_PREREG.md`). The informational bottleneck (§8) is domain-specific acoustic texture, not insufficient model expressiveness, so the representation question is "what discards texture while keeping leak information," not "what is bigger."

Ranked by expected value against that specific question:

1. **Cross-channel coherence as an explicit feature** (new idea, not in the original V2 document). The current gate is confirmed time-constant and therefore cannot be exploiting inter-sensor timing/coherence at all. Magnitude-squared coherence between the two channels is physically motivated (a real leak is a broadband, spatially coherent source; site-specific ambient noise may be less coherent across sensors) and cheap to add as an auxiliary input. This is a natural candidate for "discards site-specific single-channel texture, keeps a physically leak-relevant cross-channel cue" and has not been tried anywhere in this project.
2. **Contrastive/self-supervised pretraining on this project's own unlabeled real audio** (see §6.5) — directly targets domain-invariant representation learning using exactly the texture-dominated data this project already has, without needing the label confound resolved.
3. **Log-mel / multi-resolution STFT front end** — cheap drop-in ablation, independent of whichever alignment/adaptation method is chosen; general-audio and bioacoustic cross-dataset transfer evidence (OpenBEATs, bird-song embeddings, §1) is spectrogram-based, not raw-waveform-based, which is at least a point in its favor worth testing rather than assuming raw waveform is fine.
4. **Pretrained general-audio embeddings (VGGish/YAMNet/PANNs)** — demoted per §1 (confirmed within-dataset only, no cross-dataset evidence; also tuned to speech/music bandwidth, not this project's 2 kHz band limit).
5. **Full foundation-model-scale SSL build** — still not an October deliverable; promoted from "not credible" to "a credible November+ direction" given §1's corrected evidence.

None of these replace the encoder; (1) and (3) are cheap parallel ablations that should run alongside whichever adaptation method (§6) is chosen, not gate it.

## 8. The informational bottleneck, stated directly

**What distinguishes leak from non-leak acoustics across real domains, with currently available data?** The honest answer, from evidence already in this project (not new speculation): **within one real domain, a trivial loudness-free spectral classifier already separates the classes well** (`features_1ch` logreg, within-dataset AUROC: Hong Kong hydrophone 0.90, Dongguan 0.89, Mendeley accelerometer 0.86, Mendeley hydrophone 0.85, Hong Kong noise logger 0.58) — **but none of the four methods already tried (logreg, CNN from scratch, CNN pretrained on synthetic, frozen-encoder probe) carry that signal across a leave-one-source-out split** (§2A table), and where they land near chance, they don't even agree on direction.

This pattern — easy within-domain, chance-level and inconsistent across-domain — is the signature of a classifier learning **domain/session-specific acoustic texture that happens to correlate with label because of the confound in §3**, not a shared physical leak cue. It is not an architecture-capacity problem (the same encoder gets 0.971 in-domain on Dongguan); it is a representation-invariance problem. This directly supports prioritizing §6/§7's texture-discarding candidates (AdaBN, coherence features, contrastive pretraining on unlabeled real audio) over architecture scale-up, and argues against expecting any alignment-loss trick to manufacture information that was never recorded — if the signal genuinely isn't separable from site identity in the Hong Kong/Dongguan data (§3), no loss function fixes that; only Mendeley (and possibly the unused Hong Kong MEMS accelerometer data, §3) can currently test whether a real, site-independent leak cue exists at all.

## 9. The flagship experiment

- **Training domains**: synthetic (Model E/F physics) + Hong Kong + Dongguan (full labels). Used as training signal only — their internal confound limits what they can *teach* about leak-vs-texture separation, but does not invalidate using them as a source of real-world acoustic variation.
- **Validation domains (checkpoint-dev)**: a slice of Hong Kong/Dongguan's held-out groups carved out from, and disjoint from, the frozen-test slice (fixes the best-of-30-on-the-same-set bias R2 already flagged) + a small Mendeley Looped slice reserved only for method/hyperparameter selection, disjoint from the frozen-test Mendeley recordings.
- **Held-out test domain**: Mendeley Looped frozen-test slice — the only source not structurally confounded by site identity (§3). Hong Kong/Dongguan rotations (`f_nohk`/`f_nodg`-style) are kept and reported, but explicitly labeled **secondary/diagnostic** ("can the model rank never-trained groups of this source"), never as a leak-generalization claim.
- **Labels available**: full labels for synthetic + Hong Kong + Dongguan; **zero** Mendeley labels in main training (preserves the zero-shot test, per §2's ordering).
- **Whether target data are used**: three phases, run and reported in this order (not jumped past):
  - **Phase A — true zero-shot**: no Mendeley data of any kind. Answers §2A.
  - **Phase B — unlabeled-target adaptation**: AdaBN recalibration using unlabeled Mendeley Looped windows only. Answers §2C, and is attempted *before* any labeled fallback, per your instruction.
  - **Phase C — labeled k-shot fallback**, only if A and B both fail: k ∈ {1, 5, 10} labeled Mendeley recordings (drawn to include both classes, which Mendeley alone permits cleanly per §5), linear probe on frozen features. Answers §2D, explicitly secondary.
- **Architecture**: Model F's existing dual-channel CNN encoder, plus a cross-channel coherence feature as a parallel ablation arm (§7.1) — tested alongside, not gating, the main alignment/adaptation result.
- **Representation**: raw waveform (unchanged) as primary; log-mel/STFT front end as a parallel, non-gating ablation (§7.3).
- **Loss**: main detection BCE (unchanged) + an unsupervised marginal alignment term between synthetic and each real source's pooled features (CORAL, or whichever method `TL-Fault-Diagnosis-Library`'s own tables actually favor — §6.2, gates this specific choice, not the experiment's existence). Class-conditional alignment restricted to synthetic and the small Mendeley Looped sample only, since Hong Kong/Dongguan are single-class per group.
- **Baselines**: RMS/loudness, spectral logreg (`features_1ch`, already built), current Model F with no alignment/no adaptation (prior-approach control, **not the success bar**), domain-randomization-only (Model F's own augmentation already serves this role — no redundant baseline needed).
- **Seeds**: 3, matching existing project practice.
- **Metrics**: AUROC on logits, bootstrapped over recordings/groups; detection rate and false-alarm rate at a pre-registered threshold, secondary.
- **Statistical test**: AUROC 95% CI lower bound exceeds both 0.5 and the matched spectral-logreg baseline's CI upper bound, replicated across all 3 seeds — unchanged from the original V2 document's M section, which was already sound.
- **Success criterion**: see §10.

## 10. Positive result, defined before running

A positive result means: **the new model performs substantially better than the trivial amplitude/spectral baselines on the Mendeley Looped frozen-test slice, with zero test-set tuning, replicated across all 3 seeds, at the earliest phase (A, then B, then C) where it clears the bar in §9.** Beating Model F is neither necessary nor sufficient — Model F is a control baseline for context, not the scientific standard, exactly as you specified. A result that only clears the bar at Phase C (k-shot) is reported as a k-shot success, explicitly distinguished from a zero-shot or unlabeled-adaptation success. A result that clears no phase is reported as a replicated negative result under the corrected method, consistent with this project's existing practice for Model F's own H2/H3 outcomes.

## 11. Final decision

**B. The current data are sufficient only for a Mendeley-centered zero/few-shot real-domain-generalization experiment (§9); additional data are required to answer the full, multi-site version of the original question.**

What's sufficient now: the flagship experiment in §9, run on Mendeley Looped as the held-out target, with Hong Kong/Dongguan rotations reported honestly as secondary/diagnostic. This can start in Week 1 without waiting on any new data.

What's missing, specifically, for the fuller claim ("generalizes across independent real-world domains," plural, without the confound caveat): genuinely paired leak/no-leak recordings at the same physical site. Concrete, actionable leads already in this project, not hypothetical future collection:
1. Resolve the Hong Kong MEMS accelerometer sampling-rate question (`experiments/public_data.py`'s own docstring already flags this data as likely paired before/after recordings, currently unused) — a Week 1, non-blocking, parallel-track task.
2. Reprocess Dongguan's 8 matched material-zone-sensor trial pairs (§3) as a small, separately-valid, less-confounded sub-benchmark — a Week 1 code change to `experiments/public_data.py`'s grouping logic, not new data.
3. Read the Xu, Liu, Liu & Zayed (2026) Hong Kong→Dalian domain-transfer paper in full (§1) — it may describe or point to a genuinely independent, non-confounded second real site, and reports a result (>10% improvement from domain adaptation) directly relevant to method choice.

None of these block starting §9's flagship experiment; they run in parallel during Week 1, exactly as the original V2 document's Week 1 scope intended, just corrected to the actual state of the evidence.
